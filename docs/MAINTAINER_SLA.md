# Maintainer Review SLA

> Governs response and review timelines for issues and pull requests in the
> Forge project. See also: `internal/reviewsla/` for the programmatic checker.

---

## Overview

Forge maintainers commit to the following Service Level Agreements (SLAs) for
community contributions and issue reports. These targets apply to all
repositories under the `teragrid/forge` organisation.

---

## SLA targets

| Event | Target |
|-------|--------|
| Initial triage (label, comment, or assignment) | **48 hours** after creation |
| First substantive review comment on a PR | **7 calendar days** after submission |
| Merge or reject decision on a PR | **30 calendar days** after submission |
| Response to a security report | **3 business days** after receipt |

"Substantive review" means a review that addresses the PR content — not just
a "thanks, will look at it soon" message.

---

## Exceptions

The following situations may extend SLA windows:

- **Holidays / maintainer leave** — announced in advance in GitHub Discussions.
- **Major release crunch** — typically the 2-week window before a vX.0 release.
- **External dependency blocks** — e.g. waiting on an upstream fix.
- **Complex architectural changes** — PR author will be notified with an
  expected review date.

---

## SLA dashboard

The SLA dashboard is generated by the `forge sla` command (powered by
`internal/reviewsla`):

```bash
# Snapshot current PR state from GitHub API
forge sla snapshot --out .forge/sla-snapshot.jsonl

# Show dashboard
forge sla dashboard --snapshot .forge/sla-snapshot.jsonl
```

Example output:

```
=== Forge Maintainer Review-SLA Dashboard ===
Policy: triage<48h0m0s  review<168h0m0s  merge<720h0m0s
Open PRs: 12  Breaching: 2

  PR#47 "feat: add GCP Cloud Run adapter" age=210h0m0s [MERGE]
  PR#51 "fix: path traversal in scaffold" age=55h0m0s [REVIEW]

2 SLA breach(es) require attention.
```

---

## Automated SLA checks

The `.github/workflows/sla-check.yml` workflow runs weekly and posts a
dashboard summary as a GitHub issue comment. Maintainers are pinged via the
CODEOWNERS assignment.

---

## Escalation

If a PR is approaching or past the SLA window and has not received a review:

1. Author pings `@teragrid/forge-maintainers` in the PR.
2. If no response within 48 hours, author opens a GitHub Discussion in the
   "Maintainer Coordination" category.
3. A senior maintainer will assign a reviewer or provide a timeline.

---

## Metrics

SLA compliance is tracked monthly and reported in the maintainer meeting notes
(linked from GitHub Discussions). Target: ≥ 90% of PRs within SLA.
